# 目录摄影（程序工位 + 一次看图选页）

> 执行身份：程序负责打开页面、滚动、截图和计数；选哪一页由模型看截图决定（每次处理最多两次看图调用）。模型不可用时退回程序规则。

## 拍什么

拍一眼能看出"有多少、有什么"的页面：

- 组件源：能看到一批渲染出来的组件预览的页（目录页、首页往下的组件展示区）；整站都没有预览墙时，用列出全部组件名的目录；
- 合集：作品网格；
- 素材站：素材网格；
- 设计规范：基础规范页（色彩 > 字体 > tokens）；
- 工具：功能或案例页；
- 知识站：文章列表。

## 怎么选

像人一样先看再选，不凭链接文字猜：

1. 站长或 Agent 通过"指定采集页"给出的页面，直接拍，不再比较；
2. 审查员要求"重新取景"时，先在原页面重新取景，不合格再进入比较；
3. 其余情况进入**看图比较**。候选来自：阅读员拍摄单的首选和备选、预览规则打分最高的链接、Storybook 文档页、sitemap 与 llms.txt 里像目录的页、导航里的其他入口，以及首页（往下滚，跳过已作为首屏的第一屏）。前几页里分数更高的目录链接也加入比较（第二跳）。
4. 每个候选：打开 → 依次看前四屏，停在程序数到预览最多的那一屏 → 截图。跳转到已看过页面、空白、和首屏重复的直接略过。最多看 8 页、约 150 秒。
5. 把全部截图编号并排交给模型，问"哪一张让人一眼看出这个站有多少东西"。模型同时说明依据：`rendered-items`（看到渲染出来的条目）或 `name-list`（只有名字目录）；都不行就交回 `none`。

## 计数与判定

- 程序的预览计数随截图保存，只当提示。纯 CSS 动效、SVG 图标网格会被数成 0，所以经过看图比较的目录不再按计数拒收。
- 模型不可用时：组件源需要计数至少 4 个才放行；其他类型按候选顺序取第一张合格的图。
- 看图判定结果（依据、理由、比较了几页、每页计数）写进截图证据，后面的截图审查、风格判定和发布闸门都能看到。

## 情况与处理

- **候选页 404 或打不开：** 只说明这个子页面失效，跳过它，不代表整站无效。
- **相同截图：** 和首屏几乎一样（感知哈希距离 ≤ 6）就略过。
- **客户网站展示（Showcase）、Logo 墙、评价：** 不是站点自己的条目，模型不会选它。
- **Storybook：** 保留 `path` / `id` 等路由参数，不能把它们当跟踪参数删掉。
- **看完都不合格：** 以"需要重新选页"退回候选库，并列出看过的页面。站长或 Agent 可以用"指定采集页"给出页面，从这一站继续，已有成果保留。
