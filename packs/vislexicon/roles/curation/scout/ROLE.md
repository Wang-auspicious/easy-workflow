# 侦察员（程序工位）

> 执行身份：确定性程序，不调用模型。本文写给站长、主调度和后续维护者：它做什么、怎么判断、出错时怎么处理。这里写的每一种行为都由 `packs/vislexicon/scout.ts` 实现，并有测试覆盖。

## 为什么有这个岗位

以前单个 Agent 入库质量高，是因为它先在浏览器里读完整页文字，再决定拍哪页、写什么。侦察员把这段"跑腿"变成一个程序：在模型开始思考之前，就把站点卷宗准备好。这样阅读员、分类员、复核员拿到的是同一份完整资料，不用各自去抓首页的前两千字。

## 做什么（按顺序）

1. **HTTP 取首页：** 拿到状态码、最终地址、标题、描述。结果缓存 6 小时。
2. **在共享浏览器里渲染首页：** 自动拒绝 Cookie、隐藏浮层，读取可见全文、标题层级、每个链接所在区域（导航 / 正文 / 侧栏 / 页脚），并识别建站框架（Docusaurus、Storybook、VitePress、Next.js、Nextra、Astro、Mintlify、GitBook、GitHub Pages、Sandpack 演示）。Storybook 会额外展开它的故事索引。
3. **用 HTTP 并行取站点文件和关键页：**
   - 站点文件：`llms.txt`、`llms-full.txt`、`sitemap.xml`（含子 sitemap）；
   - 关键页：目录候选、关于、定价、许可、文档首页，各取正文开头。
4. **找到 GitHub 链接时读仓库：** 元数据、SPDX 许可、LICENSE 原文及其网址、`package.json`。
5. **把这些整理成卷宗，** 写进案卷的"侦察卷宗"一段。

## 情况与处理

| 情况 | 处理 |
|---|---|
| 网址无效、首页 404/410 | 失败，不可重试，从候选库排除并保留出处 |
| 证书错误 | 失败，亮红灯通知站长；绝不跳过校验 |
| 登录墙、验证页 | 失败，保留内置浏览器页面，亮红灯，等站长登录后按原因重试 |
| HTTP 被拒（403、反爬）但浏览器能打开 | 以浏览器渲染结果为准，继续 |
| 浏览器名额已满或渲染失败，但 HTTP 有正文 | 用 HTTP 正文建卷宗，并在过程里注明 |
| GitHub API 额度用完 | 卷宗里注明"仓库读取失败"，交给事实核验员用 `fetch_text` 补读 |

## 资源

- 运行时按 http 资源排队；需要渲染时再向资源调度器借 1 个浏览器页，用完立即归还。
- 浏览器页总数默认最多 8 个，内存不足时自动减少。

## 给主调度的提示

- 某站卷宗明显很空（正文不到几百字、链接很少），多半是单页应用渲染失败。看过程记录里是否有"浏览器渲染失败"。
- 侦察员的结果是后面所有 Agent 的共同基础。它失败时，不要跳过它直接重试分类。
