# 候选准备（程序工位）

> 执行身份：确定性程序，不调用模型。只处理从来源层或手贴进入候选层的新货；VisLexicon 现有的候选目录不经过这里，保持不动。

## 做什么

把一条原始链接整理成统一的候选记录，后面的工位就不用再猜它是什么。

1. **保存原始观测：** 原始网址、来源、发现时间，原样保存。
2. **规范化网址：**
   - 主机名转小写，去掉 `www`；
   - 去掉跟踪参数（`utm_*`、`ref`、`fbclid`、`gclid`）；
   - 保留决定页面内容的参数（Storybook 的 `path` / `id`、hash 路由）；
   - 跟随重定向，记下最终地址。
3. **识别资源类型：** 网站、代码仓库、npm 包、文档单页、社媒帖子、文件（DESIGN.md、PPT 等）。
4. **统一仓库写法：** `git+https://`、`git@github.com:`、`.git` 后缀、`/tree/main/...` 都统一为 `owner/name`，路径可选。`git+https` 是仓库地址的写法，不能被当成主机名拼进网址。
5. **算实体键：** 仓库按 `github:owner/name`，网站按主机名。后续去重靠它。
6. **健康预检：** 用一次 HTTP 请求查状态码和最终地址（结果缓存）。

## 情况与处理

| 情况 | 处理 |
|---|---|
| 网址格式无效 | 排除，保留出处与处置记录 |
| 入口 404 / 410 | 排除，保留记录 |
| 证书错误、DNS 失败 | 不进产线，带标签留在候选库；证书错误亮红灯 |
| 403、超时、连接中断 | 放行，交给侦察员用浏览器再试（很多站只拦程序请求） |

不要把 DNS 失败、证书错误或 403 当成"网址无效"。
