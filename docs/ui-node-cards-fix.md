# 节点等大与消息点击白屏修复

## 原因与修复

工位消息点击后会打开任务详情。真实事实契约中的 `facts.license`、`facts.pricing` 是 `{value, sources}` 对象，旧详情页直接把许可对象作为 React 子节点。可稳定复现 `Objects are not valid as a React child`，随后整个工作区卸载、白屏。

详情页现在读取事实的 `value`，兼容历史字符串字段，同时检查标题、分类、风格和文案等动态数据。摘要保留 `pricing` 的值，完整来源证据仍在详情和日志中；摘要字段不会再意外覆盖完整详情的其他成员。每张详情卡增加独立错误边界，遇到其他损坏记录时仍能关闭或重试，画布和其他工位保持可用。

所有来源、程序、Agent、闸门、库存以及折叠线路统一为 **240 × 112**。来源区采用两列，三排工段重新安排，字体、图标、内边距与状态行统一。布局版本为 7，旧坐标保存在 `previousLayout`。

## 验证

- 类型检查通过，UI 单元测试 45/45。
- 布局测试 14/14：尺寸一致、没有卡片重叠、连线避开节点、展开其他线路后位置独立。
- 报告、详情缓存与数据投影测试 23/23。
- `npm run test:ui:nodes`：v1/v2 逐条点击工位消息，打开结构化事实与旧字符串任务，关闭后可再次打开；故意损坏记录也只出现可关闭的局部错误卡。
- 实际浏览器检查：34 个展开节点都是 240 × 112，标题完整；2000 × 1240 和 1366 × 768 视口均截图检查。截图与数据均来自隔离测试项目。
- 原生桌面检查 25/25 通过，包含启动、浏览器、截图、只读保护、重启和关闭。一次原生浏览器截图等待超时后，在独立复测中全部通过。
