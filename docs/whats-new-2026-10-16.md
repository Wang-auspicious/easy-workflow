# Easy Workflow v0.2.0 · 2026-10-16

## 新增

- **新增「待人工」逐件审核页。** 左边是排队的条目，每条写着它为什么停下，比如「组件特写摄影重做了 2 次仍不合格」。右边是这件货的首屏、目录、特写三张截图和简介。你能做三件事：
  - **按我的意见重做**：选一个工位，写一句怎么改，就退回给它。系统会按停下的原因预选工位。
  - **从原工位继续**：只有技术故障转人工的条目才有这个按钮。
  - **先跳过**。

  没有「直接放行发布」：后端没有这个接口，发布闸门也不允许跳过审查。
- **新增三个进入审核页的入口**：顶部状态栏的「待人工 N ›」、左栏新增的「待人工」图标（带数量角标），以及画布上「待人工」库卡片里的「去审核」按钮。
- **新增内核 v2（默认关闭）。** 每件货有自己的状态（就绪、运行、等待、停放、完成），存进同一个数据库，不再靠重放全部历史来推算当前状态。退回和重试按一张固定的表执行。迟到的结果会被丢弃。跨线投递不会重复建货。默认仍是 v1，你的真实项目没有迁移，也没有切换。
- **新增 Agent 预算与交接（v2）。**
  - 原来每次最多调 10 次工具，现在改成按 token 和时间算预算。默认值是最近 50 次成功用量中位数的 5 倍，没有历史时用 60000；时间默认 15 分钟。
  - 用到 90% 时提醒 Agent 交接，到 100% 时强制交接，交接后进入「等预算」状态。
  - 你可以点「继续」，预算翻倍，并在原会话上接着做。会话不会因为退回理由变了就重开。
- **新增共享黑板和讨论室（v2）。**
  - 工位之间可以对某个字段提出结论、质疑和答复，并互相追问。答疑最多 2 次，讨论最多 3 轮。答疑等待期间会让出模型名额。
  - 讨论不出结果时由程序裁判，裁判不了再交给声明的 Agent。
  - 所有写入和事件在同一个事务里，重启后不会重复发言，也不会重复提问。
- **新增跨货经验（v2）。** 工位在一件货上学到的经验可以用到下一件。每个工位最多 5 条，每条 300 字以内。你可以在工位的「说明」页里删除，删除会留下审计记录。
- **新增三条消息流的拆分（v2）。** 进展、对话、需要你处理的事分开显示：
  - 聊天顶部一行总结：在跑 / 等资源 / 等模型 / 已发布 / 需要你。
  - 最多 5 张「需要你处理」卡片，带「处理」按钮。
  - 每个讨论室有「显示进展」开关，状态会被记住。
  - 对话和进展各保留最近 1000 条，进展再多也不会把对话挤掉。
- **新增启动快照（阶段 A）。** 六个组件定期把状态存成快照，启动时只补快照之后的事件，不再从头重放约 18.7 万个事件。快照损坏或版本不对时自动退回全量重放。还加了一个离线生成快照的命令：`npm run snapshot`。
- **新增 Kev-9B 决策模型接入**：`server/decision-model.ts`、`packs/vislexicon/decisions.ts`。程序工位可以用一组有限的固定问题请你自部署的模型做判断。地址和 key 只存在本机的 `~/.pi/agent/easy-workflow/` 里，仓库中没有。
- **新增外部投料与续跑**：`external-intake`、`intake-continuation`、`intake-captures`。从外部丢进来的一批网址可以接着上一轮继续跑，已有的截图会复用。
- **新增发布队列（publication outbox）。** 发布记录先写进队列，再和外部文件对账。写入失败时不会丢掉还没发完的条目。
- **新增特写补充输入**：`capture-supplement`。人工检查点用尽后，可以补一张新的特写证据重新判定。它不算一次重试，也不会改动原始截图。
- **新增群组**：`shared/rooms.ts`。群组从流程图推出来：只有「干完活必须对另一个人说话」的结构才会建群，比如退回环、跨段移交。
- **新增工作流搭建页**：`WorkflowBuilder`。
- **新增启动等待页**：`app/loading.html`。
- **新增外部 Bot 测试题**：`benchmark/test.md`，可以直接发给 OpenBot、dsh-bot 等外部 Bot。答案文件 `answer-key.PRIVATE.md` 只在本地，已设为不提交。
- **新增 v2 规格文档**：`docs/spec-v2-kernel.md`。

## 改进

- **画布改成一屏看完整条策展线。** 读懂与判定、取证与风格、核验与发布三排，加上来源接入、候选与分流，整条线能放进一屏。其他折叠的线移到右侧一列，连到它们的线画成浅色。
- **卡片放大到 176×82，名字 14.5px，加了一点阴影和渐变的立体感。** 卡片底部不再显示「试 386 次」这类数字，改成一句现在的状态：
  - 正在处理 xxx.com
  - 排队 3 件
  - 已暂停
  - 上一件没有通过
  - 空闲

  截图类工位还会带两张最新的小缩略图。v2 下排队数和运行数直接取自内核。
- **外框对齐。** 第一排三个框上下沿一致；三排的左右边对齐；来源坞贴着左边线。拖动卡片后仍保持对齐。
- **连线拐角从 18px 改成 6px，卡片圆角从 11 改成 8。**
- **工位详情改成固定 380×540，像聊天一样看它在做什么。**
  - **动态**：一件货一个气泡，最新的在最下面，比如「正在处理…」「特写 ✓」「没通过：没有合格的特写」。点气泡打开那件货。
  - **说明**：直接把这个工位的 ROLE.md 排成正文，顶上一句写明不合格时退回给谁、最多几轮。Agent 工位可以在这里换模型；v2 下这里还会显示跨货经验。
- **右侧聊天改成 Grok Bot 风格。** 先看到会话列表：主调度排第一，有动静的群按时间排，安静的群收起来。点进去是气泡对话，同一个人 5 分钟内连续说的话合在一起。工位自动播报默认折叠，显示为「N 条工位播报已折叠」。主调度的对话里不再混入工位播报。
- **告警弹窗分成「需要你处理」和「不需要你处理」两组。** 系统类告警按类型收进折叠组。只有需要你处理的事才会显示红点。
- **左栏去掉了「999+」角标。**
- **布局版本升到 6。** 之前手动拖过的位置会回到新默认位置，旧坐标保存在布局文件的 `previousLayout` 里。
- **启动更快（v2 阶段 A）。** 以下数据来自验收副本（约 18.7 万事件）：
  - 冷启动：13.5 秒降到 9.8 秒。
  - 有快照时连续三次：5.7 / 2.9 / 2.9 秒。
  - 后端打包成一个文件，首轮读模块从约 8.5 秒降到约 0.3 秒。
  - Playwright 改成第一次用到时才加载。
  - 文档内容没变时不再重写。
- **全量测试从约 685 项增加到 780 项。** 内核、黑板、重试、交接、恢复都有专门的测试。

## 修复

- **修复两件货同一毫秒入场时顺序被打乱的问题。** 现在严格先来先跑。
- **修复续会话的讨论回合只发文字、没发截图的问题。**
- **修复交接后重复提交没有报错的问题。**
- **修复问答和讨论的恢复问题：** 重启后不会重复发问、不会多扣一次答疑额度；自问和互相循环提问会被拒绝；过期的回合不能再发帖，也不能覆盖会话。
- **修复人工退回或停放后讨论室仍在跑的问题。** 现在会同时关闭讨论室并取消执行；迟到的结果不会覆盖新一轮。
- **修复打包版缺少 `style-contract.mjs` 导致风格校验库加载警告的问题。**
- **修复测试服务偶尔分到浏览器禁止的端口（6697），导致 8 个测试连锁失败的问题。**

## 尚未完成和已知问题

- **v2 的真实长运行验收没有通过。**
  - 在副本上用 30 个站跑了约 19 分钟：155 次尝试，约 193 万 token。
  - 停下时 12 件在跑、14 件排队、4 件停放，0 件发布。
  - 有 6 件在「等预算」里超过 10 分钟没有变化。
  - 讨论室的真实改正和讨论记录还没有凑够（D.10）。
  - 强杀重启测试被权限策略拦下，一次也没执行。
- **启动 5 秒目标没有完全达到**：首轮 5.7 秒。目前不再继续追这几秒，但没有把它记成通过。
- **阶段 F（主管定时复盘、自动微调补丁）还没开始。**
- **全量测试没有全绿。** 剩下的失败几乎都是 Windows 在测试临时目录里重命名文件夹时报 `EPERM`，每次失败的不是同一批，单独跑能通过；这部分代码这次没改。另有 1 项调度器测试偶发退出，原因没有查清。
- **还没有决定是否把默认内核切到 v2。** 切换前要先在副本上把长运行跑通。
