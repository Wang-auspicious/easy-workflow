# 持续任务与恢复验收

日期：2026-10-11（America/Los_Angeles）。本文记录后端修复；聊天区域的展示由独立界面工作继续。

## 已确认的问题

- 一轮标题写了“候选 × 100”，实际只领取 20 个。主调度在一个总限时 120 秒的回答里轮询、分两次各取 10 个，超时后没有后台目标继续补料。原轮次是 0 发布、18 待重试、1 人工挂起、1 排除。
- 普通连接错误也被工厂的默认分支写成 `auth` 提醒。裸 HTTP 403、匿名可选接口及密码组件示例也可能触发登录判断。
- ProtoPie 已取得公开图库和其他公开页面的内容，随后遇到可选 Cloud 登录链接，整段采集直接中止。受限子页不能推翻已经取得的公开证据。
- 看图选择的编号与依据没有交叉校验；`index=0` 搭配正向依据会静默变成“没有合格页面”。现在要求模型修正矛盾的结构化输出。
- 文案审查的真实失败记录包含 6 次模型调用、7 次工具调用，总计约 120.6 秒后被整个工位的截止时间截断。请求超时和完整工位的工作预算必须分开。
- 按网站名查询会选到最早的任务记录：同一条目已经经过四次重试，调度器仍读到第一次失败。现在别名查询使用当前轮的最新有效记录，精确任务 ID 继续支持历史查询。
- 10Web 的三次重拍均停在同一首屏。定位说明把英文标题写在中文句子的引号中，旧程序拿整段文字去匹配单个 DOM 文本节点，匹配失败后静默截图；同时没有应用审查员的重新取景说明。

## 后端行为

`run_batch` 持久保存目标、在途上限和前段窗口。已有条目计入目标，重试不增加独立条目数；前段腾出空位时补料。网络故障按退避从检查点继续，选页失败交阅读员结合拒收记录重新查找；恢复有上限，未解决项不算成功。明确暂停、停止以及结束的语义分别保留。

恢复名额优先交给靠后工位，避免已经取得证据、只差审查的任务被前段阅读重试挤住；名额和重试次数仍使用同一上限。

主调度以单次模型请求为超时边界，保存原始对话、已完成工具结果与写入回执。瞬断、用户停止、关机和重试耗尽分别记录；支持继续、即时补充、排队跟进及重连状态校准。一次健康对话里的有意重复操作不被误去重；恢复中的不确定写入先核对，不盲目重放。

工位采用独立的请求时钟和总工作时钟。默认总预算覆盖受限数量的工具、提交、校验修复和续答，显式工位硬截止保持原语义。单次请求超时可以保留工具结果后续答一次；长工具不会被前一个已经完成的模型请求计时器误取消，总工作超时或用户取消仍传到工具。

该工作预算沿用从输入准备完成后开始计时的边界；前置输入抓取仍使用自己的网络时限，不把它描述成整个 attempt 的统一硬截止。

访问提醒依据真实页面证据。系统故障页面回收，用户页面保留，同一登录现场不重复堆积。可选受限子页记录失败后尝试公开备选。重新核验不能靠关闭红灯冒充解决；暂停时通过的核验保存恢复标记，恢复也受在途上限控制。

特写摄影提取说明中的可见标题，并合并嵌套元素和换行后的文字来定位。审查员的新定位优先于旧拍摄单；找到目标后，舞台选择留在目标视口内。明确锚点找不到时返回阅读员重新选页，保存实际定位与滚动结果，不把首屏冒充重拍成功。新提示文案也验证其失败标签，保证继续走 Agent 恢复。

## 验证与边界

- 新增和关联的批次、会话、真实 HTTP、浏览器、核验队列及视觉输出契约回归，覆盖暂停、重启、取消、重复请求、工具回执、登录误判和公开页面备选。
- 原全量首轮为 255 通过、1 失败、2 超时取消、1 条件跳过。失败来自旧的验证 fixture 缺少新增状态字段，已更新并单独通过。两个浏览器测试在所有业务断言通过后达到全局 30 秒限制；释放测试资源后的组合复测 11 项通过，两次浏览器均正常退出，未证实产品清理泄漏，未通过增加超时掩盖问题。
- 后续定向恢复回归 24 项通过；真实打包 Electron 启动、共享浏览器、窗口退出、重启、只读数据保护及截图/录屏检查通过。右侧界面的隔离验证不替代后端真实运行验收。
- 工位两种时钟使用真实 Pi 与本地 SSE/工具作缩放复现：多个健康请求累计超过旧整段限制仍能完成，单请求超时续答保留工具结果，显式总截止仍按原时间中止；闭源适配、用量、取消和图像选择契约一起回归。
- 最终工位、批次、Pi、闭源适配、取消、核验和看图契约联合回归 **35/35 通过**，无跳过。后端包的 136 个源码/编译文件逐一核对一致，只更新后端而保留已安装的界面产物。
- 随后对真实运行发现的别名查询问题做失败复现：4 项先失败；修复后专项与真实 HTTP 控制回归 **17/17 通过**。精确历史查询、跨轮重试、相同时间顺序和名称冲突均覆盖。
- 定位和重拍通过真实浏览器截图像素回归；与舞台、iframe、Storybook 相邻测试合计 **22/22 通过**。覆盖旧定位与新审查目标同时有效、跨 DOM 标题、舞台不跳回首屏、缺失目标及错误标签。独立访问当前 10Web 页面遇到验证，不将这些本地回归称为当前官网重拍已成功。
- 对原项目进行一致性备份后，在同一轮次接入真实 100 个目标，按在途上限 8、前段窗口 4 继续。真实主调度只读查询完成，已恢复的 ProtoPie 继续从公开图库采集。历史失败与检查点均保留。
- 第二次后端更新后，无需再次发聊天指令，原轮次与 100 个目标自动恢复，检查时为 24 个已领取、8 个在途。此处只证明持久调度和重启续跑，不把仍未发布的条目计为发布。

实际站点发布质量仍由原有审查和发布闸门决定。持久目标已生效、测试通过、能继续运行，都不等于 100 个站点已经全部完成或发布。
